# 使用装配策略

[English](USAGE_en.md) · [安装](INSTALLATION.md) · [来源接入](INTEGRATION.md)

当前资源的块、插槽、稳定定位和兼容策略见[资源布局](RESOURCE_LAYOUT.md)。
## 接入方式

选择“标准版”使用 DSH 公开接口，选择“进阶版”要求 addon 与准备后的核心。旧策略仍为进阶。标准版历史/输入必须保留且有序，不能任意 depth 或添加 assistant 贡献；user 的 context 与 pre-step 都进入原始日志；[历史筛选](HISTORY_POLICY.md)可在后续请求中清理旧注入及旧系统/上下文副本。Tavern 提供插槽优先（RP 默认）和身份优先两个标准参考方案。见[后端规则](BACKENDS.md)。

标准历史清理在官方轨迹中可能产生大量「上下文 —」审计条目；整轮折叠可暂时缓解，按来源折叠等待官方接口。见[已知显示缺陷与操作方式](HISTORY_POLICY.md#官方轨迹显示限制)。

## 入口与界面

设置侧边栏中的“提示词装配”入口始终可用，点击后从设置切换到独立策略编辑器；当前会话尚未发送第一条消息时也可打开。界面按“策略库 → 装配规则与预览 → 历史筛选规则与预览 → 会话应用 → 界面设置”排列，分区用标题和分割线区分。语言设置只改变界面显示，不属于提示词内容或会话策略。

## 保存与应用

在策略库创建、导入、导出或选择策略。内置策略不能改名或删除，修改后保存为副本；用户策略可以编辑。保存更新策略库，应用则把所选配置保存为当前会话的快照。修改策略库中的同名策略不会自动更改已应用的会话；要让后续请求使用修改结果，重新应用。

“保存规则”只更新策略库；“保存并应用到当前会话”先保存未保存的装配与历史筛选修改，再应用保存后的策略。保存失败时不会应用；未修改的内置策略直接应用，不额外创建副本。

使用“使用此策略新建会话”时，明确选择工作区；只有一个工作区时可自动选择。插件先创建会话并绑定策略，再打开会话，因此第一条请求就能使用该配置。没有全局默认策略。关闭策略或未应用策略时使用 DSH 默认装配；缺少 addon 或协议 1 时仍可编辑、预览旧进阶策略，应用时明确拒绝；标准策略可在 stock 核心应用。

独立面板与 Tavern 内嵌面板操作同一策略库和同一会话绑定，没有插件优先级。两个入口先后应用时，以最后一次成功应用的快照为准；仅修改草稿或保存策略不会覆盖已应用快照。双方的当前应用状态会同步刷新，未保存草稿仍留在各自编辑器中。

## 三个原生模块与消息角色

| 模块 | 请求中的内容 |
| --- | --- |
| 官方基础指令 | DSH 当前系统指令及已注册插件提供的系统段落；角色是 system |
| 原生历史 | 先前用户消息、助手回复和工具结果，保留原始角色 |
| 本步输入 | 本次新提交的输入，不包含在只读预览中 |

进阶策略取消模块勾选会排除它对后续请求的贡献，不删除 DSH 持久记录，也不会偷偷补回输入框中的文字。一般连续对话启用三项；只要当前输入而不要历史，可启用“官方基础指令＋本步输入”。

自定义文本默认角色为 user；标准版可选 system，assistant 仅限进阶。文本是否相同不能替代消息角色：当前 DeepSeek 适配器把前置 system 正文放进独立系统字段；若没有任何对话消息，线上的 messages 会为空。因此关闭本步输入后，仍可用非空 user 自定义文本作为请求输入；仅有官方基础指令或 system 自定义文本不足以形成该接口的对话请求。预览提供 ASSEMBLY_SYSTEM_ONLY 诊断；完全空的装配以 ASSEMBLY_EMPTY 拒绝执行。其他 provider 的合法角色和对话限制以其接口为准。

## 模块、自定义文本与位置

模块添加菜单只列出当前来源能提供的独立内容。每个模块展开后说明包含什么、来自哪里、能否编辑及修改入口。修改正文通常需要到对应来源插件；这里配置是否发送、位置、角色、深度与保留方式。

来源只有分散内容时，不需要出现在模块列表，仍可提供文本解析器。使用“添加自定义文本”选择解析器并填写正文。DSH 文本解析器仅展开 DSH 提供的 `{{变量名}}`；缺失变量明确报错。安装 Tavern 后提供一个统一 Tavern 解析器，依次处理受限只读 EJS、内容引用和 ST 宏。第三方解析器使用各自语法，不自动运行其他来源的代码。

在「资源位置」配置来源声明的宏目标、世界书位置和独立注入类别；空位置也支持开关与排序，不需要先加载资源。按用户选择的排序优先级生成「装配结果」。同页展开的来源配置可设置支持的历史深度、角色及保留方式。“每次重新装配”在每个请求重新求值，不累积副本；“累积快照”保留变化后的正文及历史锚点。关闭或卸载来源后旧快照停止注入，已记录请求正文仍可读取。完整工具调用和结果不能拆开。

## 预览与实际请求

“装配结果”使用当前草稿、可读资源和已保存历史，不应用策略、不发送模型请求，也不包含输入框草稿。随机宏使用固定样例；尚未初始化或需要修复的来源应返回明确诊断。

“查看最近实际请求”在进阶版读取 DSH 持久保存的 request/assembly；安装 Tavern 后，标准版也可读取其记录的原生请求边界及来源明细，反映请求当时的内容。更新前未记录边界的旧请求可能无法读取，下一次发送后再查看。更改策略或卸载来源不会改变该记录；它不代表供应商一定收到请求。此按钮只读最近请求，不能替代另一条历史记录。Tavern Trace 则按记录 ID 读取当次已核验详情，保留全部角色消息；system 按来源小模块展示，模块正文与完整 system 原文分别展开，缺少来源证据时明确说明。

## 提供方卸载与重新安装

可选预设列表只包含当前提供方注册的内置预设和用户保存的策略。插槽优先和身份优先内置预设由 Tavern 提供；没有 Tavern 时不应出现在列表。旧会话已应用的内置快照保留，并单独说明提供方未注册，不会重新成为全局可选预设。

重新安装来源会恢复它的注册项。会话原有选择、明确关闭状态及在独立模式中重新应用的策略不会被旧配置覆盖。缺失来源的模块报告诊断并跳过；用户保存的策略仍保留，来源恢复后按其规则解析。迁移和卸载不改写原生历史。

标准版沿用原生 durable events；Tavern Trace 可核对 system/context 历史引用。独立面板不会把当前历史伪装成完整冻结请求记录。

Tavern 开场草稿也可使用此按钮预览所选资源与草稿变量；草稿尚无原生历史，预览不含待发送输入，不创建会话或调用模型。实际请求需发送后查看。
