# 资源位置与装配结果

[English](RESOURCE_LAYOUT_en.md) · [使用](USAGE.md) · [后端边界](BACKENDS.md)

编辑器分成两页。「资源位置」展示来源声明的所有潜在内容位置，支持开关和拖动；有当前会话或开场草稿时自动解析资源，将能确定单一位置的类别同步到结果顺序，空类别及分散在多个位置的类别保留配置位置并说明；「装配结果」读取当前资源，按所选排序策略装配，展示实际产生的正文、来源、角色、顺序及处理原因。查看最近实际请求是独立的只读操作；当时记录不会随草稿改变。

## 配置的粒度

位置是稳定的来源类别，不是本轮触发条目。预设主提示词、后置指令、深度注入和其他正文分别配置；角色描述、性格、场景、示例和用户描述标出对应宏/插槽；世界书声明前后组、对话示例附近、作者注释附近和深度注入。来源可以声明更多位置。

MVU 声明变量状态与更新指令的独立注入位置。已经展开到世界书或模板正文里的变量引用仍属于宿主正文，不能把任意变量值伪装成独立消息。模板来源声明独立注入和深度注入。当前没有资源或触发内容的位置仍留在配置页；注册来源当前 `moduleAvailable:false` 也可预先配置，不代表调用了该资源。

来源、文本解析、消息身份、投递、留存及原生上下文开关放在配置页的「来源、文本与投递设置」。结果页不提供另一套位置编辑器，也不把未加载的占位行伪装成实际输出。

标准后端选择「保留来源身份」时，system 内容归入历史前的 system 区域，user 内容归入原生 user 投递区域；插槽优先级在角色与运行时边界内决定顺序，不要求为跨边界插槽改写身份。世界书深度也不能覆盖此身份选择。选择「允许按位置适配」时，才按插槽前后及深度 0/1 映射身份。官方基础指令的开关独立于身份处理，始终可以关闭。

装配结果中的错误会保留到重新校验成功；修改或保存配置不代表校验通过。界面在应用当前策略或恢复默认策略前，使用当前会话/开场草稿重新预览，失败则不应用。校验不包含未发送输入，未来资源变化仍由实际请求重新校验。

## 优先级与开关

拖拽即自定义位置，始终覆盖自动定位，不需要再调整“用户排列”的优先级。点击“跟随资源位置”恢复自动定位。只有拖动的类别变为自定义位置，其余类别继续跟随自动规则；其内部条目仍保持来源顺序，原宏/插槽不重复发送该内容。

自动定位优先级仅包含 `preset`（预设插槽与宏引用）、`resource`（资源自带位置与深度）和 `default`（来源默认顺序）。越靠上越优先，每项内容采用最高优先级的适用规则；三项的六种排列均可保存。预设胜出时内容保留在引用位置，资源胜出时采用相对锚点或深度，默认胜出时采用来源列表顺序。

自定义位置通过稳定的来源类别锚点记录，例如位于 `input/content` 之前；末尾用 `anchor:"end"` 表示。自动定位完成后应用这些锚点，因此自动规则改变锚点位置时，自定义位置会跟随。锚点不存储本轮资源条目或列表序号，多个手动位置按锚点依赖定位；循环引用拒绝装配，缺失目标按回退设置处理。

标准后端在允许按位置适配时，先按优先级确定逻辑位置，再转换身份和原生发送位置。自定义位置的类别可放到历史或本步输入之后；拖到列表末尾时，即使后续类别为空，也位于其余装配内容之后，并采用 user 步骤前注入。保留来源身份时仍服从身份边界，无法跨越的移动会说明运行时冲突。

DSH 原生历史、工具事务、已留存快照和投递区域属于不可覆盖的硬约束，单独说明，不伪装成可拖动的优先级项。标准后端不会把 system 改成 user 来伪装任意排列；身份适配须单独选择。开关控制是否包含内容，不参与位置优先级比较；关闭位置排除独立内容及宏/插槽引用，但不删除持久历史和既有快照，标准后端必须保留历史与本步输入锚点。

新策略默认自动优先级为预设、资源、默认。兼容读取旧四项列表时移除 `user`，保留另外三项的相对顺序；旧 `priority:user|preset` 及未设置优先级的布局采用默认三项。已有手动位置也改为始终覆盖自动定位；读取不会直接重写磁盘，保存时使用新表示。旧具体资源 `overrides` 保留且不被自动规则覆盖，可在界面清除。允许按位置适配时，通用位置排列先于原生身份转换，旧具体资源覆盖仍在转换后的合法区域内处理。

## 协议与存储

来源协议 1 的 descriptor 可选增加 `positions`，通过既有 GET `sources` 返回，无新端点。每项为 `{id, name:[中文,English], match?:{field?,group?,depth?}, anchor?:{sourceId,fields?,side}, macros?:string[], configurable?:boolean, note?:[中文,English]}`。匹配显式块 `positionId`，再匹配声明的字段/组/深度，最后使用无 match 的默认项；无声明的来源保留一个 `content` 位置。宏名称只是解释来源对应关系，不增加解析语法。`anchor` 声明资源自带的相对位置。当前加载器不支持的世界书命名出口仍显示，但标记为不可配置并说明不产生内容。

策略仍为格式版本 1，`layout` 可包含：

```json
{
  "version": 1,
  "source": "preset-slots",
  "identity": "preserve",
  "fallback": "source-order",
  "priority": ["preset", "resource", "default"],
  "overrides": [],
  "positions": [
    {"sourceId":"worldbook","positionId":"after","enabled":true,"placement":"list","anchor":{"sourceId":"worldbook","positionId":"before","side":"before"}},
    {"sourceId":"worldbook","positionId":"before","enabled":true,"placement":"source"}
  ]
}
```

位置不存储资源 ID、条目 ID、状态 revision 或激活列表。换预设、换世界书以及新增触发条目时重新求值。`fallback` 继续选择回退并诊断或拒绝装配；未知来源/位置产生 `POSITION_SOURCE_MISSING`。已知位置没有本轮内容仍保留配置行；若被自定义位置显式选为锚点，则按缺失定位设置处理。

`positionRows(preset,sources)` 生成完整配置清单；`configurePosition` 构造开关/顺序修改。`normalizeLayout`、`describeResourceLayout`、`withBlockMove` 保持旧合同，后者只用于具体资源覆盖。新结果节点含 `positionId`/`positionDecision`，`resourceLayout.positionDecisions` 汇总开关和位置决策，`POSITION_CONFLICT` 说明身份或运行时边界为何限制自定义位置。`resolvedPositionRows` 将可确定的位置投影到配置列表，列表刷新不写入策略或已应用快照。

预览和发送共用解析与排序路径。标准后端预览不含未发送输入，且 user context 可能复用历史快照，所以当前装配结果不等同于完整网络请求；冻结结果以已记录实际请求为准。未注册插件不能由界面凭空提供内容。

验证：`node --test test/resource-positions.test.mjs test/plugin-client.test.mjs`。`test/resource-layout-host.test.mjs` 使用 `DSH_ASSEMBLER_STOCK_ROOT` / `DSH_ASSEMBLER_CORE_ROOT` 和临时 profile，验证保存重载、换资源、优先级排列及离线真实请求。浏览器验收覆盖空类别配置、后台位置解析、开关、拖拽、优先级切换、结果及保存应用。

自动规则按优先级确定归属，手动位置排除在自动规则之外。结果中的 `sortingStages` 分别列出自定义位置和各自动规则定位的节点，它是归属说明，不是可编辑的执行流水线。资源卡片在加载具体资源前展示来源声明的稳定性；结果卡片直接说明已有原生消息、系统更新、上下文/步骤前注入、仅本次请求和单独留存的装配快照是否进入原生历史。两个列表均只通过拖拽调整顺序，不提供上移下移按钮。
